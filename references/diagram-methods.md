# 工程文档怎么选图

先用一句话写出读者看完这张图要能回答的问题，再决定节点和连线的含义。整份文档逐项判断三类图的用途。需要发散、解释关系和拆解或汇报时分别提供，核心架构图和业务时序图按工程需要另画。局部改动按当前问题选图，保留用户点名要求的图。

| 读者要做什么 | 选图 | 如何判断画对了 |
| --- | --- | --- |
| 围绕主题找线索、联想方案、帮助记忆或头脑风暴 | **思维导图** | 从一个中心主题向外展开，分支是关键词和关联线索。还能沿任一分支继续发散。 |
| 理解概念如何组成知识结构，或解释依赖、条件和有依据的因果 | **概念图** | 每条重要连线带关系词。按方向读两个节点和连线，能组成一句可判断真假的陈述。 |
| 把一个问题拆成可判断、可调查或可交付的子项 | **逻辑树** | 根是待回答的问题。同组分支使用同一拆分维度，叶节点有验证办法或交付物。 |
| 把已有依据组织成汇报、大纲或演示讲稿 | **金字塔** | 顶层直接回答核心问题。同层论点属同类、顺序有理由，每一组能共同支撑父结论。 |

## 思维导图 · 博赞的规则与工程适配

**原始规则**以横向空白空间为底，从中心画代表主题的图像，主枝从中心发散，次枝接到主枝。用有机曲线、不同颜色和图像辅助联想，主枝更粗。每条枝线上写一个关键词，继续用支枝展开关联。头脑风暴阶段先收线索，明确决策留到后续核验。 [Tony Buzan，《Mind Map Handbook》原作节选](https://www.everand.com/book/234807671/Mind-Map-Handbook-The-ultimate-thinking-tool)

**现代工程适配**保留中心、放射、关联与短标签。复合术语可作为一个语义单位保留，长说明进详情或正文。颜色同时配文字或形状，图像帮助识别主题。窄屏可重排成可读的树，分支可跳到正文。联想线表达关联，因果判断交给带关系词的概念图与事实核验。这里的适配服务于可访问、操作和版面需求。

## 概念图 · Novak 与 Cañas

先写焦点问题，例如「审核回执如何关联到原资料？」提取名词性的概念，按该问题从一般到具体组织。用有方向的连线和具体关系词构成命题，例如「审核回执 → 指向 → 审核记录」。保留能解释跨分组依赖的交叉链接，样例放在对应概念旁。依赖可写成「依赖」「读取」「限制」，有方向的因果关系附条件或证据。待证因果显式标作假设。 [Novak 与 Cañas，IHMC 原始技术报告](https://cmap.ihmc.us/docs/theory-of-concept-maps)

## 逻辑树与金字塔 · 拆题和论证

- **逻辑树从问题往下拆。** 先说明范围和目标，再选拆法，例如按发生环节、组成因素、独立方案或待验证假设拆解。每组检查是否有重叠、漏项或层级混杂。需要覆盖范围时，用 MECE（相互独立、合起来覆盖所定范围）检查同层。对待查项保留验证条件，叶节点收敛到可核实事实、测试或任务。分支依赖可单独用概念图交代。 [Conn 与 Sarrazin，McKinsey 的问题拆解实践](https://www.mckinsey.com/capabilities/strategy-and-corporate-finance/our-insights/how-to-master-the-seven-step-problem-solving-process)
- **金字塔把思考整理成可汇报的结论。** 先把事实分组，提炼该组支持的判断，再逐层归纳出一个回答。在呈现时从这个回答往下讲，下一层回答「为什么」或「怎样做到」，同层观点类型一致，按时间、结构、重要性或演绎顺序排列，最后接证据。需要交代背景时，用 SCQ（情境、变化、问题）引到答复。结论证据不足时，顶层写清当前判断及验证条件。 [Barbara Minto，金字塔原理与 SCQ](https://www.barbaraminto.com/concept)

## 组合与验收

同一项目可先用思维导图搜集「范围、证据、操作、实施」的线索，再用概念图讲「回执怎样追到资料版本」，用逻辑树拆「审核为何仍未完成」，最后用金字塔汇报「为何先交付单页审核闭环」。会发生的操作顺序用流程图，跨方请求和返回用时序图，部署位置和系统边界用架构图。每张图回答一个具体问题，正文引用同一事实来源。

验收时逐张读图。检查能否从中心找到关联词，从概念边读出命题，从逻辑树的叶节点得到验证办法，从金字塔的依据回到顶层结论。图默认可见，重要关系能在窄屏或文本替代中读到。
