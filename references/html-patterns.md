# HTML 呈现与交互

## 已确认的呈现基线

以用户当前认可的成品优先。缺少本轮参照时，[工程文档样页](../assets/engineering-doc-example.html)给出默认骨架和示例密度。沿用浅底、紧凑页头、顶部章节导航、单列正文、细线分组。核心图与步骤放在正文前部，证据、验收和长字段在相应流程后面。颜色辅助辨认正常、待核或阻断，文字明确表达状态。

| 用户认可的做法 | 评审中已否定的做法 |
| --- | --- |
| 系统边界、数据去向、处理分支直接画出来，核心图默认可见 | 大横幅、侧栏、指标卡和摘要占主要位置，实际只剩段落、表格或编号列表 |
| 用真实可理解的页码、题位、样例数据和箭头解释结果。保留已认可的同序／逆序／漏页例图与裁切示意作为领域示例 | 仅给模块名称或「识别 → 处理 → 输出」通用三步，读者依然无法判断各阶段怎么做 |
| 以使用端的操作为主线。服务端单独一栏，内部派发、并发、汇总和失败恢复单独展开 | 在两张表反复写角色，职责、请求和返回挤在同一格，内部关键决策藏在概述里 |
| 操作效率依赖控件时，展示所在界面、给分动作、合计、提交和异常。需要决定控件时提供原地可操作的对照 | 值只写成静态数字。读者看不到怎么选择、键入、确认、重试或领下一项 |
| 图内按需缩放，图框独立滚动，提供适应宽度与显示全图 | 超长图把整页撑开，滚动后缩放入口难以找到 |
| 先梳理核心功能，再删重复描述。验收跟在相应流程之后 | 用少量概括代替核心功能，或用离线演练与验收台账充当架构图和工程解释 |

## 一份正文的四种读法

| 读法 | 在 HTML 中怎样体现 |
| --- | --- |
| 像 Markdown 一样查阅 | 语义标题与稳定锚点定位章节。可读的说明、关键例外和来源就近放置，长字段、源码或证据用折叠或链接。 |
| 像轻量 PRD 一样评审 | 先写目标、使用者、本期范围和完成标准。功能概述每项一两句话，业务条件、异常和待定参数放到对应流程。 |
| 像思维导图一样理解 | 画出项目目标与功能、架构、操作、实施之间的层次关系。分支能直达正文，节点名称对应真实业务。 |
| 像演示 PPT 一样讲解 | 先说目标，再讲功能、架构和关键操作，最后落到实施顺序与验收。每站有一个结论和必要图示。可用上一项／下一项或明确的讲解路线复用原章节。 |

给架构分配足够篇幅。对每个相关层说明边界、职责、输入、去向和数据所有权，对关键链路补协议、失败分流和恢复条件。功能摘要短一些，阅读深度通过图与明细提供。

## 先选能解释问题的视图

先按[图示方法](diagram-methods.md)判断读者要发散主题、解释关系、拆问题还是组织结论。随后针对真实系统细节补架构图、时序图、流程图或状态图。

- **架构图**表达组件边界、职责、数据来源、所有权及流向。工具名放在实际依赖它的步骤旁，写清解决的难点和采用状态。
- **时序图**以当前读者的操作为主线，将客户端与服务端单独成栏。标谁发起、对端返回什么、何时阻断。服务内部的分发、事务或汇总需要时另做视图。
- **流程或状态图**展示进入条件、互斥分流、待处理状态、回流和完成边界。关键分支配有能看出差异的短案例。
- **草图**让操作可见。静态草图用真实语义结构和代表内容。控件选择、操作次数或错误恢复影响决策时，加入能实际操作的最小交互，保持演示数据与真实服务的边界。
- **表格**承载需要横向对比的契约和规则。保持可读，不为填满列而重复角色或常规响应。

优先沿用项目现有图示方式。使用 D2 时，嵌入已渲染的 SVG，源码另行折叠。D2 无法使用时，可用原生 SVG 或带连线、箭头与分区的 HTML 表达关系。正文里的图须可见，折叠源码、图标、仅有标题的 `figure` 和验收表均不算已画图。已有获认可的图示按反馈局部修订。

## 只补足图以外的契约

接口表优先用「发起端目的｜接口或触发｜业务输入与关键返回｜服务端职责」。关键返回是下一步依赖的结果，例如受控上传入口、领取凭据、修订和任务 ID。通用参数、常规响应和字段全集按需查原文。服务端内的去重键、原子操作、有效版本和统计口径等决策由流程图和短说明承载。

只列难确定的核心数据结构。说明稳定标识、关联对象、谁写入、版本或替换规则、有效性和缺失值语义。对定时任务、大对象、分块合并、图像识别等步骤标注依赖的库、算法或组件，并区分已有用法与候选。

## 展示会改变操作效率的细节

对少量固定分值用平铺单选，对许多档位或小数用数字输入。需要比较时让两种控件操作同一示例并共用草稿，显示实时合计和规则约束。明确 0 与空白、提交确认、失败后草稿、键盘顺序和下一项的时机。用有对照的实际样本检验速度及误操作。这是评分例子。其他场景也用真实操作差异选择控件。

## 交付形态

沿用项目术语与语言，以自包含 HTML 为默认。用语义标签、稳定锚点、图示文字替代、响应式布局、可见焦点及有意义的按钮。长表和大图各自控制溢出。可折叠来源、样例及原文，关键判断留在可见层。每个新增交互实际操作一次，检查正常和异常状态。静态资料和模拟状态明确标识，展示内容的真实性由证据决定。
